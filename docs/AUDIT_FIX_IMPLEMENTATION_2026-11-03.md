## 2. Код

### 2.1 D3/D7 — fail-closed по ключу

```python
API_KEY_REQUIRED = os.getenv("API_KEY_REQUIRED", "1").strip().lower() not in (
    "0", "false", "no", "off",
)
```

В `lifespan` сервер отказывается подниматься без ключа:

```
RuntimeError: API_KEY обязателен (API_KEY_REQUIRED=1 по умолчанию), но не задан.
Задайте API_KEY в окружении или в .env. Для локальной разработки на loopback
отключение задаётся явно: API_KEY_REQUIRED=0.
```

В guard добавлена вторая линия (если ключ исчез из окружения после старта) —
**503** вместо тихого пропуска запроса.

Почему именно так, а не «ключ обязателен всегда»: владельцу нужен локальный
режим без ключа (он же и запускал приёмку). Fail-open сохранён, но только как
**явное** `API_KEY_REQUIRED=0` — то есть решение о снятии защиты принимается
осознанно и видно в конфигурации.

Дополнительно: `README.md` теперь предлагает `--host 127.0.0.1` вместо
`0.0.0.0`, а `.env.example` объясняет, как выставлять API наружу (ключ +
SSH-туннель/reverse-proxy с TLS).

### 2.2 N2/N5 — CORS стал внешним слоем

`CORSMiddleware` перенесён **после** guard: в Starlette последний добавленный
middleware становится внешним, поэтому CORS обрамляет проверку ключа и
добавляет свои заголовки ко всем ответам, включая 401.

* Хардкод `Access-Control-Allow-Origin: http://localhost:3000` из ответа 401
  удалён — origin вычисляется по `allow_origins`.
* Список origin задаётся переменной `API_ALLOWED_ORIGINS`
  (по умолчанию `localhost:3000,localhost:8000`) и **не дублируется** в guard.
* Чужой origin не получает разрешающего заголовка — переход не утекает.

### 2.3 D5 — наблюдаемость отказов

* Каждый отказ увеличивает `auth_failures` и пишется в лог с путём и origin.
* `GET /health` теперь отдаёт `auth_required` (требование ключа) и
  `auth_failures` (счётчик с запуска) — режим безопасности виден без чтения логов.

## 3. CI и приёмка

### 3.1 §7.4 — docs-only PR получают проверки

```yaml
push:
  branches: [ main ]
  paths-ignore: ['docs/**', '**/*.md']   # push остаётся дешёвым
pull_request:
  branches: [ main ]                      # paths-ignore убран намеренно
```

Для `push` фильтр сохранён — CI не должен запускаться на каждом docs-коммите в
`main`. Для `pull_request` он убран: иначе PR, меняющий только документацию, не
порождает статус-checks и не проходит правило ветки `main` — внешний
контрибьютор не может прислать ни документацию, ни правку в `docs/`.

### 3.2 H1-5 — смоук eval-контура

Новый джоб `Eval Smoke (10 questions, no LLM)` и новый тест
`tests/unit/test_eval_smoke_contract.py` (6 тестов):

* контракт датасета: 40 записей, все `verified`, уникальные `qid`, `validate_dataset` — OK;
* детерминированность выборки смоука;
* метрики `recall@k` / `MRR@k` / `nDCG@k` на трёх синтетических выдачах
  (идеальное попадание, полный промах, попадание ровно на 5-й позиции);
* согласованность разметки: `expected_terms` каждого вопроса встречается в его
  же `reference_answer`.

Тест не требует индекса, моделей и сети — поэтому реально исполняется в CI.
Индекс-зависимая часть H1-5 (реальный retrieval на фиксированном индексе) в CI
не воспроизводится: индекса нет в репозитории. Это остаётся открытым пунктом.

### 3.3 Тесты аутентификации расширены

`tests/unit/test_search_api_auth.py`: было 8 тестов (уровень guard) → **15**,
включая HTTP-уровень через `TestClient` без запуска `lifespan` (индекс и модели
не нужны): origin в 401 соответствует origin запроса, чужой origin не получает

   построен (сборщик, смоук, джоб с артефактом); **сама фикстура — данные
   владельца**, в репозитории её пока нет.
3. **H1-2, H1-3, H1-4, H2, H3** — не начаты; правки их не касались.
   **Раунд 4 (см. §10.2–§10.3):** H1-2 закрыт, H1-3 закрыт по механике (замеры
   p95 по режимам по умолчанию и по режиму 5 — за владельцем); H1-4, H2, H3 не
   начаты.
4. **S-46, наблюдаемость в глубину** — счётчик отказов появился, но структурных

### 10.3. H1-3 — бюджет латентности

* `src/astro_app/performance.py` — политика: default p95 ≤ 10 с, LLM-режимы ≤ 30 с,
  всё > 30 с — «экспериментальный»; роли режимов, вердикты, Markdown-таблица,
  чтение снимка замеров. Модуль чистый: не ходит в сеть и не запускает модели.
* `scripts/benchmark_budget.py` — замер поверх `scripts/eval_search_quality.py`
  (умеет `--from-report`, чтобы переоценить готовый отчёт без моделей), код возврата
  `1`, если бюджет нарушен ⇒ пригоден как gate.
* `docs/PERFORMANCE.md` — политика, что именно профилируется, измеренные значения,
  инструкция воспроизведения, честный список того, что осталось за владельцем.
* `eval/dataset/latency_baseline.json` — машинно-читаемый снимок замеров
  (происхождение указано в файле: перенесён из `RESULTS_REPORTED.md`).
* Меню помечает экспериментальные режимы: по снимку это 12 «Self-RAG» (p95 37,9 с)
  и 19 «GraphRAG» (p95 33,0 с); 21 «DAT+LLM» — 29,4 с, впритык.
* `tests/unit/test_performance_budget.py` — 12 тестов на политику, роли, вердикты,
  согласованность снимка в репозитории и пометки в меню.

Что **не** сделано (зафиксировано в `docs/PERFORMANCE.md`): кэш эмбеддингов/ответов/
query expansion и параллельные вызовы LLM — это оптимизации, а не бюджет;
профилирование разделено на total / LLM / retrieval, **rerank отдельно не
выделяется**. Не измерено: p95 режима по умолчанию и режима 5 — нужен прогон
владельца с индексом и LM Studio.

### 10.4. H1-5 — урезанный индекс как CI-артефакт

* `src/astro_app/index_fixture.py` — формат фикстуры (чанки + метаданные +
  манифест с sha256), загрузка, проверка целостности и **лексический retrieval
  (BM25)** без эмбеддинг-модели, без LLM и без сети.
* `scripts/build_index_fixture.py` — сборка фикстуры из полного индекса владельца
  (сначала чанки файлов, на которые ссылаются размеченные вопросы).
* `scripts/index_fixture_smoke.py` — смоук на 10 вопросах, отчёт JSON + Markdown;
  код возврата `2`, если фикстуры нет (честно, а не «тихий успех»).
* `.github/workflows/ci-cd.yml` — новый джоб `Index Fixture Smoke`: при наличии
  `fixtures/astrology_mini/fixture.json` прогоняет смоук и **публикует фикстуру и
  отчёт артефактом прогона**; при отсутствии — notice «сборка за владельцем».
* `tests/unit/test_index_fixture_contract.py` — 11 тестов: формат, манифест,
  обнаружение подмены файла, BM25-ранжирование, смоук, запуск скриптов.
* `fixtures/README.md` — как собрать и что попадает в фикстуру.

**Честное ограничение:** фикстура содержит дословный текст корпуса. Публикуя её
артефактом, владелец публикует этот текст; в README фикстуры и в отчёте это
оговорено, а вариант «артефактом только отчёт» предусмотрен (каталог фикстуры не
коммитится).
