# Производительность и бюджет латентности (H1-3)

**Статус:** механика готова и проверена тестами; **числа замеров — от владельца**
(нужны локальный индекс и LM Studio, в репозитории индекса нет).

---

## 1. Политика бюджета

| Роль режима | Кто попадает | Бюджет p95 | Что значит |
|---|---|---|---|
| `default` | режим по умолчанию (`modes.DEFAULT_MODE` = **«2» Граф**) | **10 с** | базовый сценарий должен быть быстрым |
| `llm` | режимы, которые ходят в LLM или формируют ответ (1, 7, 10, 11, 12, 17, 18, 19, 21) | **30 с** | генерация ответа — законный источник задержки |
| `expert` | остальные режимы | 30 с | общий потолок |
| — | всё, что **медленнее 30 с** | — | режим помечается «⏱ экспериментальный» и по умолчанию выключен |

Правило реализовано в `src/astro_app/performance.py` (чистый модуль: считает
вердикты по измеренным сводкам, ничего не запускает) и используется в двух местах:

* `scripts/benchmark_budget.py` — замер + вердикты + код возврата (1, если бюджет
  нарушен) ⇒ пригоден как gate в CI или в pre-commit;
* `src/astro_app/menu.py` — помечает в меню режимы, которые по замерам
  медленнее 30 с (данные берутся из `eval/dataset/latency_baseline.json`).

## 2. Профилирование: что раздельно измеряется

| Компонент | Как меряется | Где в отчёте |
|---|---|---|
| **total** | полное время ответа режима на вопрос | `latency_ms.p50 / p95 / mean` |
| **LLM** | время внутри перехваченных вызовов LLM + число вызовов | `llm_calls_mean`, `retrieval_ms` = total − LLM |
| **retrieval** | всё, кроме LLM (поиск + переранк + пост-обработка) | `retrieval_ms.p50 / p95` |
| **rerank** | **отдельно не выделяется** — сейчас внутри `retrieval_ms` | — |

Известный пробел: переранк (ColBERT/E5/mxbai) живёт внутри `retrieval_ms`, и
отличить его от поиска текущий harness не умеет. Разделение требует
инструментовки внутри режимов (`dense.py`, `bm25_hybrid.py`) — это отдельная
доработка, не входящая в текущий блок.

## 3. Измеренные значения (снимок)

Источник: `eval/dataset/latency_baseline.json` (машинно-читаемый снимок,
перенесён из `eval/dataset/RESULTS_REPORTED.md`). Происхождение цифр —
живой прогон автора на индексе `astrology_test` (1369 чанков), 40 размеченных
вопросов H1-1, модель `google/gemma-4-e4b` (LM Studio). Сырые отчёты лежат в
`outputs/` (вне репозитория), поэтому **независимого воспроизведения из
репозитория нет** — для него нужен свой индекс.

| Режим | Роль | p50 | p95 | Бюджет | Вердикт |
|---|---|---|---|---|---|
| 2 «Граф» | default | 545 мс | **не измерен** | 10 с | unknown — p95 требует прогона |
| 1 «Multi-vector» | llm | 6,2 с | 12,8 с | 30 с | ok (но как default — нарушил бы 10 с) |
| 21 «DAT+LLM» | llm | 21,1 с | 29,4 с | 30 с | ok |
| 19 «GraphRAG» | llm | 16,6 с | 33,0 с | 30 с | **experimental** |
| 12 «Self-RAG» | llm | 23,8 с | 37,9 с | 30 с | **experimental** |

Как это читать:

* **режимы 12 и 19 помечены экспериментальными** — по умолчанию выключены,
  в меню у них стоит пометка «⏱ экспериментальный»;
* **режим 21 впритык** (29,4 с при бюджете 30 с) — при другом железе или более
  длинном ответе он перейдёт в экспериментальные;
* **режим по умолчанию «2» — самый быстрый из измеренных** (p50 545 мс, LLM не
  нужен), и именно поэтому он выбран default'ом в H1-2: режим 1 при p95 12,8 с
  бюджет 10 с не выдерживает;
* **p95 режима 2 пока не измерен** — вердикт по нему честно «unknown», а не
  «ok». Это первое, что стоит закрыть прогоном.

## 4. Как воспроизвести и переизмерить

```bash
# 1. Поднять LM Studio с моделью google/gemma-4-e4b на http://localhost:1234/v1
# 2. Замерить бюджет на своём индексе (режимы 1, 2, 5, 21 — 5 добавляется,
#    чтобы у режима-кандидата в default появились собственные числа):
python scripts/benchmark_budget.py \
    --index outputs/astrology_test \
    --modes 1,2,5,21 \
    --warmup \
    --out outputs/reports/budget.json \
    --markdown-out outputs/reports/budget.md

# 3. Переоценить уже сохранённый отчёт H1-1 (без моделей):
python scripts/benchmark_budget.py --from-report outputs/reports/eval_after_llm.json

# 4. Обновить снимок в репозитории:
python scripts/benchmark_budget.py --from-report outputs/reports/eval_after_llm.json --update-baseline
```

Код возврата `scripts/benchmark_budget.py`: `0` — бюджеты соблюдены, `1` — есть
нарушение, `2` — в отчёте нет сводок (например, отчёт пустой).

## 5. Что осталось за владельцем

| Шаг | Почему нельзя закрыть в репозитории |
|---|---|
| p95 режима 2 (default) | нужен индекс + прогон на 40 вопросах |
| p95/p50 режима 5 | режим 5 не измерялся на датасете H1-1 вообще; без него default менять нельзя |
| разделение rerank в профиле | требует инструментовки режимов (см. §2) |

После шага 4 снимок `eval/dataset/latency_baseline.json` обновляется, меню
перестаёт помечать старые режимы и начинает помечать новые — без правок кода.
