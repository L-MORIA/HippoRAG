### 3.3 D4 (constant-time) — ⚠️ исправлено с регрессом

`secrets.compare_digest` действительно подключён, и для ASCII-ключа поведение корректно (неверный ключ → 401, верный → 200).

**Но:** `secrets.compare_digest` не поддерживает не-ASCII строки — сравнение кириллицы вызывает `TypeError: comparing strings with non-ASCII characters is not supported`. Исключение не обработано, поэтому **любой** запрос к API при таком ключе падает с **500**, а не 401:

```
API_KEY=секретный-ключ, запрос без ключа   → TypeError: comparing strings with non-ASCII characters is not supported
API_KEY=секретный-ключ, запрос с ASCII-ключом → TypeError: comparing strings with non-ASCII characters is not supported
```

Для русскоязычного проекта это не экзотика: кириллический ключ в `.env` — естественная ошибка пользователя, а симптом (500 на всех маршрутах, включая `/health`) выглядит как падение сервера, а не как неверная авторизация. Клиент по RFC 7230 такой заголовок передать не может в принципе — то есть «правильный» ключ с кириллицей становится недостижимым, а сервер при этом не отвечает 401.

**Рекомендуемый фикс (одна строка):** сравнивать байты или хэши, а не строки:

```python
if not secrets.compare_digest(provided.encode("utf-8"), API_KEY.encode("utf-8")):
```

или

```python
if not secrets.compare_digest(
    hashlib.sha256(provided.encode()).digest(), hashlib.sha256(API_KEY.encode()).digest()
):
```
