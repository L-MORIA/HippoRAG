# H2-3. Упаковка: Docker CPU-only и one-command start

**Дата:** 2026-11-06
**Статус:** реализация готова, локальные проверки пройдены; приёмка
«установка на чистую машину ≤ 15 мин» **не проведена** — на машине разработки
нет Docker, чистой VM и LM Studio.
**Задача:** [ROADMAP_REVISION_DEEPSEEK.md](./ROADMAP_REVISION_DEEPSEEK.md) §9.3,
H2-3.

---

## 1. Итог

Добавлены четыре способа запуска, не меняющие поведение поиска и генерации:

| Способ | Команда | Что делает |
|---|---|---|
| Windows, один файл | `start.bat` | создаёт `.venv`, ставит пакет, копирует `.env`, запускает UI |
| Linux/macOS | `./start.sh` | то же самое |
| Docker (CPU-only) | `docker compose up --build` | собирает образ и поднимает UI на `127.0.0.1:8000` |
| Вручную | `uvicorn astro_app.web:app ...` | прежний способ, остаётся рабочим |

Общий слой проверок — `scripts/start.py`; проверка LM Studio — отдельный
`scripts/check_lmstudio.py` на стандартной библиотеке, его можно запустить до
установки зависимостей.

## 2. Что добавлено

| Файл | Назначение |
|---|---|
| `Dockerfile` | `python:3.11-slim`, CPU-колёса `torch==2.5.1+cpu`, non-root `appuser` (uid 10001), healthcheck `/ui/config` |
| `docker-compose.yml` | сервис `hipporag`, порт только на `127.0.0.1:8000`, `host.docker.internal`, bind-mount `outputs/`, `data/`, `temp_uploads/`, `cache/` |
| `.dockerignore` | не тащит в образ `.git`, `.env`, `outputs/`, `data/`, `cache/`, тесты, eval и docs |
| `start.bat` | выбор Python 3.10–3.12, `.venv`, `pip install -e .`, запуск `scripts/start.py` |
| `start.sh` | то же для Linux/macOS, с проверкой версии Python |
| `scripts/start.py` | проверки Python, `.env`, LM Studio, индекса и API-ключа; запуск uvicorn |
| `scripts/check_lmstudio.py` | `GET /v1/models`, сверка id модели, коды возврата 0/1, `--json`, `--quiet`, `--no-model-check` |
| `tests/unit/test_lmstudio_check.py` | 18 тестов проверки LM Studio |
| `tests/unit/test_start_script.py` | 23 теста one-command слоя |
| `tests/unit/test_packaging_assets.py` | 11 контрактных тестов Docker/скриптов/`.env.example` |

`Dockerfile` не содержит LM Studio: она работает на хосте. В контейнере
`localhost` указывает на сам контейнер, поэтому compose задаёт
`LLM_BASE_URL=http://host.docker.internal:1234/v1`. Хостовый `LLM_BASE_URL`
(обычно `http://localhost:1234/v1`) в контейнер не протекает: для переопределения
есть отдельная переменная `LLM_BASE_URL_DOCKER`.

## 3. Как запустить

### 3.1. Windows

```bat
start.bat
```

При первом запуске скрипт:

1. ищет Python 3.12, 3.11, 3.10 (или `python` в PATH) и проверяет версию;
2. создаёт `.venv` и выполняет `pip install -e .`;
3. копирует `.env.example` в `.env`, если `.env` ещё нет;
4. запускает `scripts/start.py`, который проверяет LM Studio и индекс;
5. поднимает UI на `http://127.0.0.1:8000/`.

CLI остаётся доступен отдельно: `python main.py`.

### 3.2. Linux/macOS

```bash
chmod +x start.sh   # если файл потерял бит исполнения
./start.sh
```

### 3.3. Docker

```bash
docker compose up --build
```

Откройте `http://127.0.0.1:8000/`. Проверка состояния:

```bash
docker compose ps
docker compose logs -f hipporag
```

Остановка:

```bash
docker compose down
```

Первый `--build` долгий: скачиваются CPU-колёса torch и зависимости. Первый
старт контейнера тоже долгий: embedding-модель скачивается в `cache/huggingface`
(healthcheck имеет `start_period` 600 с). LM Studio должна быть запущена на
хосте, порт `1234`.

### 3.4. Вручную

```powershell
$env:PYTHONIOENCODING = "utf-8"
$env:API_KEY = "your-secret-key"
uvicorn astro_app.web:app --host 127.0.0.1 --port 8000
```

## 4. Проверки при старте

`scripts/start.py` выполняет их по порядку:

1. **Python.** 3.10–3.12 — штатно; 3.13+ — предупреждение, но запуск
   продолжается (проект на 3.13+ не гарантирован).
2. **`.env`.** Если файла нет, он создаётся из `.env.example`. Ошибка записи
   (например, read-only каталог в контейнере под non-root) не роняет запуск:
   используются переменные окружения, переданные снаружи.
3. **LM Studio.** `GET {LLM_BASE_URL}/models`; если задан `LLM_API_NAME` или
   `LLM_NAME`, проверяется наличие этого id. Проверка отключается
   `--skip-lm-check` или `STARTUP_CHECK_LM=0`.
4. **Индекс.** Проверяется существование `SAVE_DIR`. Отсутствие индекса —
   предупреждение, не ошибка: UI откроется, PDF можно загрузить через API.
5. **API-ключ.**
   - `API_KEY` задан → запуск разрешён;
   - `API_KEY_REQUIRED=0` → запуск разрешён;
   - ключа нет, адрес loopback (`127.0.0.1`, `localhost`, `::1`) → скрипт
     автоматически выставляет `API_KEY_REQUIRED=0` и предупреждает;
   - ключа нет, адрес вне loopback (`0.0.0.0` и т.п.) → запуск запрещён.

Проверка LM Studio отдельно:

```bash
python scripts/check_lmstudio.py
python scripts/check_lmstudio.py --base-url http://127.0.0.1:1234/v1 \
  --model google/gemma-4-e4b
python scripts/check_lmstudio.py --json
```

Код возврата `0` — проверка пройдена, `1` — нет. Скрипт использует только
стандартную библиотеку.

## 5. Docker: данные и права

Compose монтирует:

| Хост | Контейнер | Режим |
|---|---|---|
| `./outputs` | `/app/outputs` | чтение/запись |
| `./data` | `/app/data` | только чтение |
| `./temp_uploads` | `/app/temp_uploads` | чтение/запись |
| `./cache` | `/app/cache` | чтение/запись |

`SAVE_DIR` в `.env` должен указывать на смонтированный каталог. Относительный
путь (`outputs/astrology_test`) разрешается от `/app`, то есть в
`/app/outputs/astrology_test`; абсолютный `/app/outputs/astrology_test` тоже
подходит.

По умолчанию контейнер работает под `appuser` (uid/gid 10001). На Linux, если
bind-mount принадлежит вашему пользователю, задайте:

```bash
export DOCKER_UID=$(id -u)
export DOCKER_GID=$(id -g)
docker compose up --build
```

или заранее:

```bash
mkdir -p outputs cache temp_uploads
sudo chown -R "$(id -u):$(id -g)" outputs cache temp_uploads
```

`data/` смонтирован только на чтение — менять его из контейнера нельзя.

## 6. Безопасность

- Порт опубликован как `127.0.0.1:8000:8000`, а не `0.0.0.0:8000`. Снаружи
  контейнер по умолчанию недоступен.
- `API_KEY_REQUIRED=0` в compose — только для локального запуска на loopback.
  Для внешнего доступа задайте `API_KEY`, `API_KEY_REQUIRED=1` и публикуйте
  порт через reverse-proxy с TLS.
- Healthcheck использует публичный `/ui/config`, а не `/health`: `/health`
  закрыт `X-API-Key`, и healthcheck без ключа всегда был бы красным.
- `.dockerignore` исключает `.env`, `outputs/`, `data/`, `cache/` и `temp_uploads/`.
- `scripts/start.py` не запускается на `0.0.0.0` без `API_KEY`, если
  `API_KEY_REQUIRED` не отключён явно.

## 8. Приёмка на чистой машине

Ниже — чек-лист, который нужно выполнить отдельно. Критерий H2-3: **≤ 15 мин**
от начала установки до первого ответа.

### 8.1. Windows

1. Чистая Windows 10/11, Python 3.10–3.12, LM Studio с моделью.
2. `git clone https://github.com/L-MORIA/HippoRAG.git && cd HippoRAG`.
3. Запустить LM Studio → Developer → Start Server (порт 1234).
4. Запустить `start.bat`, засечь время.
5. Дождаться `http://127.0.0.1:8000/`, задать вопрос по индексу.
6. Зафиксировать: время, версия Python, ответ/отказ, ошибки в консоли.

### 8.2. Linux

1. Чистая Linux-машина, Python 3.10–3.12, LM Studio на хосте.
2. `git clone ... && cd HippoRAG && ./start.sh`.
3. Проверить `http://127.0.0.1:8000/` и первый ответ.

### 8.3. Docker

1. Установить Docker Engine/Desktop.
2. `git clone ... && cd HippoRAG`.
3. Запустить LM Studio на хосте.
4. `docker compose up --build`, засечь время до `healthy`.
5. Открыть `http://127.0.0.1:8000/`, задать вопрос.
6. Проверить `docker compose ps`, логи, права на `outputs/` и `cache/`.

### 8.4. Негативные проверки

- Остановить LM Studio → `start.bat`/`start.sh` завершается с кодом 1 и
  подсказкой, а не «молча» поднимает UI.
- Удалить `.env` → он создаётся из `.env.example`.
- Запустить `scripts/start.py --host 0.0.0.0` без `API_KEY` при
  `API_KEY_REQUIRED=1` → отказ.
- Запустить на loopback без `API_KEY` → автоматический fail-open с
  предупреждением.

## 9. Ограничения

- **Windows-установщик** в H2-3 понимается как один `.bat`, а не MSI/EXE.
  Полноценный установщик с ярлыком и автозапуском не делался.
- **Docker-образ CPU-only.** CUDA не включена; для GPU нужен отдельный образ.
- **LM Studio не входит в образ.** Она должна быть запущена на хосте; в Linux
  нужен `host-gateway` (в compose уже есть).
- **Первый запуск долгий** из-за скачивания torch, зависимостей и
  embedding-модели. Это влияет на приёмку ≤ 15 мин; кэш pip/HuggingFace
  помогает только на повторных запусках.
- **Индекс не создаётся автоматически.** Нужен существующий `outputs/...` или
  загрузка PDF через `/upload-and-ingest`.
- **Нет автоматического выбора свободного порта.** При занятом `8000` задайте
  `APP_PORT` (локально) или измените `ports` в compose.
- **Нет телеметрии установки.** Время и ошибки приёмки нужно фиксировать
  вручную.

---

## 10. Откат

H2-3 не меняет формат индекса, API и golden set. Чтобы вернуть прежний запуск:

1. не использовать `start.bat`/`start.sh`/`docker compose`;
2. запускать вручную `uvicorn astro_app.web:app --host 127.0.0.1 --port 8000`;
3. при необходимости удалить `.venv`, `cache/`, `Dockerfile`,
   `docker-compose.yml`, `.dockerignore`, `start.bat`, `start.sh`,
   `scripts/start.py`, `scripts/check_lmstudio.py` и тесты H2-3.

Удаление `outputs/` и `data/` не требуется: они не входят в git и не меняются
упаковкой.
