## 3. M1 — Recall@10

Команда:

```bash
python scripts/eval_search_quality.py \
    --index outputs/astrology_test \
    --modes 2,5 \
    --k 10 \
    --warmup \
    --out outputs/reports/eval_recall10.json \
    --markdown-out outputs/reports/eval_recall10.md
```

> `--warmup` в `meta` не фиксируется; он указан, чтобы p95 не включал cold
> start. На recall/MRR/nDCG флаг не влияет.

| Режим | n | recall@10 (док) | recall@10 (стр) | MRR@10 (док) | nDCG@10 (док) | p50 | p95 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 2 «Граф» | 40 | **97.5 %** | 72.5 % | 0.912 | 0.928 | 470 мс | 588 мс |
| 5 «BM25+CE-ru» | 40 | **97.5 %** | **75.0 %** | 0.902 | 0.921 | 204 мс | 249 мс |

Что это значит:

- Поиск **находит нужный документ** почти всегда: 39 из 40 вопросов дают
  попадание в top-10 у обоих режимов.
- Поиск **по страницам** заметно слабее: 29/40 (72.5 %) у режима 2 и
  30/40 (75.0 %) у режима 5. Это чанковый retrieval; полный page-level путь
  H1-6 измерен отдельно в M7 и даёт 87.0 % page recall@5.
- Режим 5 быстрее (p50 204 мс против 470 мс) и лучше по страницам; режим 2
  немного лучше по MRR (0.912 против 0.902) — разница в пределах разрешения
  выборки из 40 вопросов.
- Режим 1 в прогон не включён. В отчёте `llm.available=false`, а режим 1
  использует LLM-переформулировку; без LM Studio он не измерялся.

> **Исправление подписи.** В исходном `eval_recall10.md` заголовок таблицы
> называл метрики `recall@5`, хотя `k=10` (это видно в `meta.params.k`).
> Форматтер `format_markdown_table` исправлен: теперь подпись берётся из
> фактического `k`. Числа в отчёте не менялись.

## 7. M6 — Ablation synonymy

Условия: режим 2 «Граф», 40 вопросов, текущий индекс. Два прогона: с
synonymy-рёбрами и с `synonymy_edge_topk=0` (без них). Сырой отчёт —
`outputs/reports/ablation_synonymy.json`.

| Вариант | `recall@5_doc` | MRR@10 | synonymy-рёбер |
|---|---:|---:|---:|
| С synonymy | **3.3913** | **0.5160** | 726 250 |
| Без synonymy | 3.0870 | 0.4931 | 0 |
| Дельта | **+0.3043** | **+0.0229** | — |

Относительный прирост `recall@5_doc` — около **+9.7 %** (0.3043 / 3.0870),
MRR@10 — **+4.6 %**. Оба показателя выше с synonymy, поэтому решение —
**оставить synonymy**. Это закрывает H1-4.

> **Осторожно с единицами.** В JSON поле называется `recall@5_doc`, но
> значение 3.3913 больше 1, поэтому это не доля и в проценты здесь не
> пересчитывается. В отчёте оно приводится ровно как в источнике; для
> вывода «synonymy помогает» достаточно знака и относительной дельты.

## 8. M7 — Grounding на golden set

Команда:

```bash

python scripts/eval_grounding.py --run --retriever grounding_astro_retriever:retrieve \
    --out-json outputs/reports/grounding_eval.json \
    --out-md outputs/reports/grounding_eval.md
```

Прогон: 36 вопросов (23 answerable, 5 borderline, 13 unanswerable), полный
page-level путь H1-6, `qa_top_k=5`.

| Метрика | Значение | Порог | Статус |
|---|---:|---:|---|
| Abstention rate (unanswerable) | 92.3 % | ≥ 90 % | ✅ |
| False answer rate | 7.7 % | ≤ 10 % | ✅ |
| Answer rate (answerable) | **100.0 %** | ≥ 90 % | ✅ |
| Citation precision | **0.621** | ≥ 0.80 | ❌ |
| Citation recall | 0.848 | ≥ 0.80 | ✅ |
| Marker validity | 1.000 | ≥ 1.000 | ✅ |
| Uncited sentence rate | 0.0 % | ≤ 10 % | ✅ |
| Answer accuracy | **73.9 %** | ≥ 70 % | ✅ |
| **Page recall@5 (H1-6)** | **87.0 %** | ≥ 80 % | ✅ |

Латентность: p50 14 234 мс, p95 25 950 мс. Это page-level контекст, поэтому
латентность выше чанкового режима 5 (p50 204 мс без LLM): сравнивать их
напрямую нельзя.

Что это значит:

- **H1-6 достигнута:** page recall@5 87.0 % (20 из 23 answerable), выше
  порога 80 %. Это тот же golden set и те же 23 answerable-вопроса, что и в
  baseline H2-6 (56.5 %).
- **Answer rate и accuracy теперь проходят пороги:** 100 % и 73.9 % против
  73.9 % и 56.5 % в baseline. Рост согласуется с ростом page recall.
- **Не проходит только citation precision 0.621.** Citation recall 0.848
  проходит: нужные источники в ответе есть, но модель цитирует и лишние
  страницы. В построчной таблице видно типичный случай: ответ с двумя
  цитатами, из которых gold только одна → precision 0.5. У `a07` — 0.25,
  у `a13` — 0.2; у `a10`, `a14`, `b03` страница не найдена → 0.0; у `a09`
  и `a16` — `source_mismatch`. То есть проблема в **выборе/сопоставлении
  цитат**, а не в доставке доказательства.
- `u11-whale-sign` — единственный false answer (7.7 %), порог ≤ 10 %
  выполняется.

> **Ограничение.** В JSON M7 не записана конкретная модель LLM. Baseline
> H2-6 снят на `google/gemma-4-e4b`; для строгого сравнения «до/после»
> модель нужно зафиксировать в следующем прогоне.

## 9. M8 — Ablation page-ретриверов

Команда:

```bash
python scripts/measure_page_ceiling.py
```

Условия: 23 answerable-вопроса golden set, 653 страницы, 7 ретриверов.
В отчёте с другой машины `index_dir` указывает на
`...\outputs\astrology_test\gemma-4-e4b_sentence-transformers_paraphrase-multilingual-mpnet-base-v2`;
локально каталог индекса ищется автоматически по `--save-dir`.

| Ретривер | R@5 | R@10 | R@20 | R@50 | MRR@10 |
|---|---:|---:|---:|---:|---:|
| **rrf_ce** | **73.9 %** | **82.6 %** | 91.3 % | 91.3 % | 0.506 |
| bm25_ce_chunk | 69.6 % | 73.9 % | 82.6 % | 87.0 % | 0.534 |
| bm25_ce | 65.2 % | 73.9 % | 78.3 % | 87.0 % | 0.529 |
| bm25 | 60.9 % | 65.2 % | 69.6 % | 82.6 % | 0.473 |
| rrf | 47.8 % | 47.8 % | 65.2 % | 82.6 % | 0.371 |
| dense_max | 26.1 % | 34.8 % | 47.8 % | 65.2 % | 0.192 |
| dense_mean | 26.1 % | 30.4 % | 39.1 % | 56.5 % | 0.171 |

**Как читать:** лучший из этих семи ретриверов — `rrf_ce` — даёт 73.9 %
recall@5 и не добивает до 80 %. Но это **не потолок полного H1-6-пути**:
M7 на том же golden set получает 87.0 %. Разница объясняется тем, что
`page_retrieval.py` добавляет keyword-boost, которого нет в упрощённых
ретриверах M8 (см. `src/astro_app/page_retrieval.py`, `_keyword_boost`).
Поэтому вывод «проблема выше retrieval» верен только для набора M8, но не
для продукта: полный page-level путь приёмку проходит.

M8 остаётся полезен как ablation: он показывает, что просто «взять страницу
вместо чанка» недостаточно; нужен полный гибрид с boost и реранком.
