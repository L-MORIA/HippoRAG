## 1. Резюме для утверждающего

Проект работоспособен в текущем «боевом» сценарии (онлайн-режим + LM Studio + sentence-transformers), но три независимых аудита сошлись в одной картине из **трёх классов проблем**:

1. **Безопасность (2 уязвимости):** два path traversal — `clean_database.py --clean-dataset ".."` удаляет весь проект вместе с `.git`; `/upload-and-ingest` записывает файлы за пределы `temp_uploads` через backslash-имя. Обе воспроизведены.
2. **Тихое искажение результата (не падает, но врёт):** цитаты указывают не на тот документ (дедуп чанков по тексту теряет метаданные), промпт QA собирается из английского musique-шаблона вместо русского астрологического, chunker выдумывает номера страниц, NER генерирует мусорные сущности из подстрок, synonymy-рёбра для русского текста не строятся вовсе. Система «работает, но отвечает странно» — самый опасный класс, т.к. не сопровождается ошибками.
3. **Сломанные режимы (падают при входе):** offline-индексация (`assert False`), StandardRAG (отладчик в конструкторе + несуществующий метод), облачный OpenAI/Azure (несовместимый контракт возврата `infer`), кэш LLM (декоратор никогда не применён), API-эндпоинт загрузки файлов (индексация в недостижимом коде).

**Сводная статистика:**

|---|---|---|
| P0 — критические | 10 | Безопасность, потеря данных, сломанные режимы |
