# Раунд 8: декларация `outlines` и проверка guided-пути настоящим пакетом

**Документ-основание:** `docs/AUDIT_OFFLINE_BACKEND_FIX_2026-11-04.md` §7.2 —
независимая верификация раунда 7 принята (вердикт «принято», новых находок нет),
и с неё снят последний непроверенный пробел: **guided-декодирование в
`hipporag.llm.transformers_offline` ни разу не проверялось с настоящим пакетом
`outlines`** — только со стабом.

**Состояние:** дефект подтверждён, декларация и код исправлены, guided-путь
проверен настоящим `outlines` в обеих ветках API, самоконтроль пройден.

---

## 1. Что было на входе

| Позиция | Значение |
|---|---|
| `main` на входе | `fbe536d` (только документ верификации раунда 7) |
| Точка входа | находка на **границе моей же правки S-3** (раунд 6): декларация `outlines>=0.0.46` в extra `offline` |
| Что делалось в раунде 6 | `outlines` объявлен в extra `offline`, чтобы модуль `transformers_offline` перестал быть неимпортируемым |
| Задача раунда 8 | подтвердить неработоспособность декларации, исправить её **и код**, закрыть пробел «guided-путь с настоящим `outlines`» |

Дефект, найденный в раунде 6, был закрыт **по форме**: пакет объявлен, импорт
на уровне модуля объяснён. Но сама декларация оказалась неисполнимой, а код
был написан под один API `outlines`, который в актуальных версиях пакета
удалён.

## 2. Находка: декларация `outlines>=0.0.46` неработоспособна

### 2.1. Воспроизведение

| Шаг | Результат |
|---|---|
| `pip install outlines==0.0.46` | pip **откатывает `numpy` до 1.26.4** (`outlines` 0.0.46 требует `numpy<2.0.0`) → `import transformers` падает: `pyarrow requires NumPy 2.0 or newer, found 1.26.4`. Остальное окружение проекта (`pyarrow`, `transformers`, `sentence-transformers`) сломано |
| `pip install "outlines>=0.0.46"` на Python 3.14 | pip выбирает последнюю версию, чей `requires_python` допускает 3.14, — **0.1.14**; у неё `outlines_core==0.1.17`, а колёс для `cp314` нет (есть только `cp38`–`cp313`) → pip собирает Rust-расширение из исходников и падает |

То есть «установить по декларации» нельзя было ни на одной версии Python:
на 3.10–3.13 — с откатом `numpy` и поломкой окружения, на 3.14 — с падением
сборки.

### 2.2. Карта версий `outlines` (по метаданным PyPI)

| Версия | `numpy` | `outlines_core` (Rust) | legacy-API `generate.json` | `requires_python` | Итог |
|---|---|---|---|---|---|
| `0.0.46` | **`<2.0.0`** | нет | есть | `>=3.8` | ломает окружение проекта |
| `0.1.5` | **`<2.0.0`** | нет | есть | `>=3.9` | ломает окружение проекта |
| `0.1.6`–`0.1.14` | без пина | `==0.1.17` | есть | `>=3.9` | колёс нет для 3.14; API устаревший |
| `0.2.0`–`0.2.3` | без пина | `==0.1.26` | есть | `>=3.9,<3.13` | только Python ≤ 3.12 |
| `1.0.0`–`1.3.3` | без пина | `==0.2.14` | **нет** | `>=3.9,<3.13` … `>=3.10,<3.14` | современный API, Python ≤ 3.13 |

Вывод: **единственная** работоспособная конфигурация — `outlines>=1.0` на
Python 3.10–3.13, и она требует **другого API**, чем тот, что написан в коде
(`outlines.generate.json` + `outlines.models.Transformers` → `outlines.Generator`).

### 2.3. Три следствия для проекта

1. **extra `offline` обещал неработоспособное.** `pip install -e ".[offline]"`
   ломал либо окружение, либо установку.
2. **Модуль бэкенда не импортировался без `outlines`** — импорт был на уровне
   модуля (`transformers_offline.py:3–4`), поэтому и в CI, и в обычной
   установке `import hipporag.llm.transformers_offline` требовал пакета
   (в тестах — стаб).
3. **Даже «правильная» установка ломала guided-путь.** `outlines.generate` в
   `outlines>=1.0` не существует: `import outlines.generate` → `ModuleNotFoundError`.

## 3. Внесённые исправления

### 3.1. Новый модуль `src/hipporag/llm/outlines_compat.py`

Скрывает различие API за одним интерфейсом:

| Что | Как |
|---|---|
| Единый контракт | `build_guided_generator(model, tokenizer, schema_model)` → callable `(prompts, max_tokens) -> list`; список **объектов `schema_model`** в обеих ветках |
| Современная ветка (`outlines>=1.0`) | `outlines.Generator(outlines.models.Transformers(...), schema_model)`; вызов `generator.batch(prompts, max_new_tokens=…)` — 1.x передаёт kwargs в `transformers.generate` как есть |
| Legacy-ветка (`outlines<1.0`) | `outlines.generate.regex(...)` по регексу из JSON-схемы; вызов `generator(prompts, max_tokens=…)` |
| Отсутствие пакета | `OutlinesUnavailableError` с подсказкой (`pip install 'hipporag[offline]'`) **и** исходной ошибкой импорта — вместо голого `ImportError` |
| Ленивый импорт | `outlines` подключается только на guided-пути; модуль бэкенда импортируется без пакета |
| Left-padding | во время генерации `padding_side` выставляется в `left` и возвращается обратно |

### 3.2. `src/hipporag/llm/transformers_offline.py`

* убран импорт `outlines` на уровне модуля, добавлен импорт адаптера;
* guided-ветка `batch_infer` вместо прямого вызова `generate.json` использует
  `build_guided_generator`; контракт ответа не изменился — `batch_infer`
  по-прежнему отдаёт список JSON-строк, как ждёт `openie_transformers_offline`.

### 3.3. `pyproject.toml`

```toml
offline = [
    "vllm>=0.6.6",
    "outlines>=1.0,<2; python_version < '3.14'",
]
```

* `outlines>=0.0.46` → `outlines>=1.0,<2`: ветка `numpy<2` исключена, современный
  API доступен;
* маркер `python_version < '3.14'`: пакет официально не выпускается для 3.14,
  и pip там всё равно не смог бы его поставить;
* **тот же пакет добавлен в extra `dev`** — теперь CI ставит `outlines` и
  проверяет guided-путь настоящим пакетом, а не стабом.

## 4. Проверка guided-пути настоящим `outlines`

Окружение: изолированный venv (**Python 3.12.3** — версия CI), `numpy 2.5.4`,
`torch 2.15.0+cpu`, `transformers 5.22.1`, модель `sshleifer/tiny-gpt2`
(2 слоя, ~2,5 МБ, CPU; chat-шаблон задаётся вручную — у модели его нет).
Проверены **две** версии пакета: `outlines 1.3.3` (современный API,
`outlines_core 0.2.14`) и `outlines 0.2.3` (legacy-API, `outlines_core 0.1.26`).

| Проба | Ожидание | `outlines 1.3.3` | `outlines 0.2.3` |
|---|---|---|---|
| A. `build_guided_generator` на схеме с ограничением длины строки | объект схемы, длина в границах | ✅ `code='ozyg'` | ✅ `code='UKox'` |
| A0/A4. `padding_side` токенизатора | не изменён / восстановлен | ✅ `right → right` | ✅ `right → right` |
| B. батч из двух промптов разной длины | два объекта схемы | ✅ | ✅ |
| C. `batch_infer(json_template="ner")` end-to-end | JSON-строки, ключ `named_entities` | ✅ | ✅ |
| C2. `batch_infer(json_template="json")` | разбираемый JSON-объект | ✅ `{}` | ✅ `{}` |
| D. free-form путь | промпт не утёк в ответ | ✅ | ✅ |

Итог пробы: **все проверки пройдены в обеих версиях пакета**.

### 4.1. Что вскрылось при этой проверке

* **`outlines` сам переводит токенизатор на left-padding «навсегда»**
  (`outlines/models/transformers.py:215`: `tokenizer.padding_side = "left"`).
  Бэкенд не должен молча менять настройки чужого токенизатора — исходное
  значение возвращается, а на время генерации `left` выставляется явно.
* **Legacy-`outlines` роняет весь батч при обрыве генерации.** У
  `generate.json` разбор встроен (`format_sequence = parse_raw`), и
  `pydantic.ValidationError` на оборванном JSON уничтожал не только
  негодный ответ, но и весь батч. Разбор перенесён в наш код: один негодный
  ответ даёт предупреждение и возвращается как есть — ровно так же, как
  потребитель `openie_transformers_offline` переживал непарсящийся ответ до
  появления guided-декодирования.
* **Ограничения схемы `outlines` соблюдает не полностью:** ограничения длины
  строк (`minLength`/`maxLength`) — да, числовые границы (`minimum`/`maximum`) —
  **нет** (проверено: при `value: int = Field(ge=0, le=9)` модель выдала
  `{"value":-448448…}`). Это ограничение самого пакета, а не нашего кода;
  на схемы проекта оно не влияет — в `MODEL_TEMPLATES` числовых границ нет.
* **Имя параметра лимита токенов различается между API:** `max_new_tokens`
  (1.x, kwargs идут прямо в `transformers.generate`) и `max_tokens`
  (legacy-API `outlines`). Адаптер переводит это в единый `max_tokens`.

`tests/unit/test_outlines_compat_2026_11_04.py` — **14 тестов**:

## 7. Ограничения и открытые вопросы

* **Offline-режим по-прежнему не подключён к продукту.** `_get_llm_class` не
  возвращает offline-бэкенды; они используются только как OpenIE-движки через
  `batch_infer`. Проблема зависимостей снята, но «включать ли offline-режим в
  продукт» — решение владельца (нужна чат-модель с `chat_template` и
  рабочий `outlines`).
* **`outlines` официально не выпускается для Python 3.14**, а проект объявляет
  `requires-python = ">=3.10"` без верхней границы. На 3.14 guided-путь
  неработоспособен, и extra этого не скрывает: пакет просто не ставится, а при
  попытке guided-вызова бэкенд даёт внятную ошибку с указанием версии.
  Ограничение `requires-python` сверху — отдельное решение владельца.
* **`vllm` в окружении не установлен** — vllm-бэкенд (он использует
  собственный guided-декодирование vLLM, не `outlines`) проверен только на
  стабах.
* **Cross-encoder `DiTy/cross-encoder-russian-msmarco`** (~700 МБ) не
  установлен — режим 5 с CE не проверялся.
