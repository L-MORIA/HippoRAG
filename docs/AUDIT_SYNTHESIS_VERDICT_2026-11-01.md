## ⛔ Условие 1 (блокирующее) — S-12 не назначен ни на один этап

**Это дыра в плане, а не в реестре.**

S-12 — потеря метаданных цитат при дедупе чанков по тексту. Это **ключевая находка всего аудита**: цитаты указывают не на тот документ, и это единственная находка, которая подрывает саму ценность проекта (цитирование источников). В моём исходном отчёте она была High (H-01), с воспроизведением.

Что происходит с ней в сводном плане:
- В **реестре** (строка 63) — присутствует, ✅ воспроизведено.
- В **резюме** (строка 24) — упомянута первым пунктом в классе «тихое искажение».
- В **плане** — **отсутствует**. Ни один этап (0–6) не содержит S-12.
- Единственное упоминание в плане — строка 201, Этап 5, в списке **тестов**: «`embedding_store` (идемпотентность, метаданные, delete)».

Проверено скриптом покрытия: 45 ID в реестре, 42 упомянуты в плане; не назначены этапу — **S-12, S-27, S-45**.

**Почему это критично:** тест на «метаданные» без фикса самого дефекта либо провалится, либо (хуже) будет написан так, что закрепит текущее неверное поведение как ожидаемое. То есть Этап 5 закрепит баг, а не исправит его. При этом после «Этап 0 проект безопасен и корректен в основном сценарии» (строка 232) утверждать это будет нельзя — цитаты останутся неверными.

**Правка:** добавить в **Этап 0** (он занимает ~2 ч, это точечная правка `embedding_store.py:63-103`), задача `0.8`:

> S-12 | `embedding_store.insert_strings`: включить `source_file` в ключ идемпотентности либо хранить метаданные списком на `hash_id` и обновлять при повторной вставке. **Приёмка:** два PDF с одинаковым колонтитулом дают 2 записи с разными `source_file`.

Это единственная правка, которая меняет статус документа с «условно» на «безусловно».

## ⚠️ Условие 2 — S-30 недооценён: API работает с пустым индексом

Реестр говорит: «конфиг зашит в код (англ. `all-MiniLM-L6-v2` вместо мультиязычной)». Формулировка верная, но **она недооценивает последствие**.

`server.py:58-61` задаёт `save_dir="outputs/astrology_test"` и `embedding_model_name="sentence-transformers/all-MiniLM-L6-v2"`. Ядро (`HippoRAG.py:129-131`) строит `working_dir` как `save_dir / f"{llm}_{embedding}"`. Проверено на диске:

```
API working_dir  : outputs/astrology_test\gemma-4-e4b_sentence-transformers_all-MiniLM-L6-v2
  exists?        : False          ← каталога не существует

Реальный индекс  : outputs/astrology_test\gemma-4-e4b_sentence-transformers_paraphrase-multilingual-mpnet-base-v2
  contents: ['chunk_embeddings', 'entity_embeddings', 'fact_embeddings', 'graph.pickle', 'graph.pickle.bak']
  chunk_embeddings/vdb_chunk.parquet: 7 900 026 bytes
```

**Что это значит:** при старте API создаёт пустой каталог и поднимает HippoRAG с **пустым индексом**, тогда как реальный индекс (7.9 МБ, 1422 чанка) лежит в соседнем каталоге с другой embedding-моделью. `/search` возвращает пустые результаты, `/ingest` индексирует в отдельный каталог. Это не «неоптимальный конфиг» — это **API, который не видит ваш индекс**.

Плюс `HippoRAG.py:133-135` создаёт каталог, если его нет, — то есть расхождение не даёт ошибки, а молча создаёт новый пустой индекс.

**Правка:** в S-30 и в этап 3 добавить: конфиг API (`save_dir`, `embedding_model_name`) должен **читаться из env** и совпадать с тем, чем индексировали; иначе API молча поднимает пустой индекс. Приёмка: `/health` возвращает число чанков > 0; `/search` по русскому вопросу находит фрагмент.

Отдельно: это стоит **поднять в P1**, а не держать в P2 вместе с «фиктивной статистикой» и «лимитом загрузки» — разные по природе вещи смешаны в одну строку реестра.

## ⚠️ Условие 3 — две фактические неточности

**(а) S-43: «версии 2.0.0 vs 2.0.0-alpha.4» — расхождения в build-файлах нет.**

Проверено: `pyproject.toml` → `version = "2.0.0-alpha.4"`, `setup.py` → `version="2.0.0-alpha.4"`. **Оба совпадают.** Расхождение только с `src/hipporag/__init__.py:5` → `__version__ = "2.0.0"`.

Формулировка создаёт впечатление, будто два build-файла противоречат друг другу. Нужно: «`__init__.py` объявляет `2.0.0`, build-файлы — `2.0.0-alpha.4`; при сборке версия в метаданных пакета не совпадёт с `hipporag.__version__`».

**(б) S-43: URL — расхождение реальное, но не «чужой репозиторий» в смысле ошибки владельца.**

Проверено: `pyproject.toml` → `Homepage/Repository/Issues = github.com/anomalyco/hipporag`; `setup.py` → `github.com/OSU-NLP-Group/HippoRAG`. Формулировка «URL чужого репозитория (anomalyco)» корректна по факту, но `anomalyco/hipporag` — это историческое имя того же upstream-проекта (переименование после перехода в OSU-NLP-Group), а не подмена на чужой проект. Точнее: «ссылки в `pyproject.toml` указывают на дореформенное имя `anomalyco/hipporag`, в `setup.py` — на актуальное `OSU-NLP-Group/HippoRAG`; привести к одному».

**(в) S-40: «~40 файлов не закоммичено» — цифра занижена.**

Фактическое состояние рабочего дерева: **50 изменённых + 40 неотслеживаемых + 13 удалённых = 103 записи**. «~40 файлов» описывает только неотслеживаемые. Формулировка «~40 файлов рабочего кода не закоммичено» вводит в заблуждение: реальный объём незакоммиченной работы вдвое больше. Для пункта «закоммитить» это существенно — потеря такого объёма при сбое куда дороже, чем предполагает план.

## Что в плане сделано хорошо и менять не нужно

- **Порядок этапов.** «Сначала то, что молча искажает результат и безопасность, затем сломанные режимы, затем качество, затем гигиена» — правильная логика, и она же подтверждена моим аудитом.
- **Этап 0 = ~2 часа, точечные правки без рефакторинга.** Реалистичная оценка: все 7 пунктов — однострочные/малые правки.
- **Развилки в разделе 7.** Все шесть — по делу, и рекомендации разумны. Особенно:
  - №1 «оставить `pyproject.toml`, удалить `setup.py`» — верно, но **только после** переноса недостающих зависимостей (S-09), иначе удаление `setup.py` отрежет часть пакетов;
  - №4 «переиндексация обязательна» — **верно и важно**: после S-11/S-15/S-16 меняются hash-ключи сущностей, старый индекс несопоставим. Это надо поднять в самое начало плана как предупреждение, а не держать в развилке;
  - №3 «кэш включить» — верно: инфраструктура уже есть (`llm_cache/`), просто не подключена (S-04).
- **Этап 2 помечен «требует переиндексации».** Это редкая и ценная пометка, которую многие пропускают.
- **Раздел 5 «признано чистым».** Моё пересечение подтвердило: `.env` без секретов, 42 теста зелёные, хардкодных ключей нет, `main.py` без дублей определений, `embedding_store.delete()` без off-by-one, `clean_pdf_text` корректен. Раздел не раздут.
- **Привязка к воспроизводимым проверкам** в приложении (строка 238-252) — то, чего не хватало большинству аудитов.
