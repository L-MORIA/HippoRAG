# FAQ HippoRAG

## Общие вопросы

### Что такое HippoRAG?

Локальная RAG-система по корпусу астрологических PDF: находит фрагменты,
генерирует ответ и проверяет, что каждое утверждение подкреплено ссылкой
`[n]`. Если ответа в источниках нет, система отказывается отвечать.

### Чем это отличается от обычного чата с LLM?

LLM отвечает только по найденным фрагментам корпуса, а не по своим знаниям.
Ответ без валидных ссылок заменяется отказом. Полный список найденных
фрагментов остаётся в диагностике, но цитатами считаются только те, на
которые модель реально сослалась.

### Работает ли система на CPU?

Да, все методы работают на CPU. CUDA не обязательна. Для режима 5 нужен
русский cross-encoder `DiTy/cross-encoder-russian-msmarco` (~700 МБ), он
скачивается при первом запуске.

### Нужен ли интернет?

Для работы — нет, если модель и эмбеддинги уже скачаны, а LM Studio запущен
локально. Интернет нужен для установки зависимостей и первой загрузки
моделей.

### Как запустить одной командой?

Windows — `start.bat`, Linux/macOS — `./start.sh`. Скрипт создаст `.venv`,
установит зависимости, проверит LM Studio и запустит UI на
`http://127.0.0.1:8000/`. Docker-вариант — `docker compose up --build`
(CPU-only, LM Studio остаётся на хосте). Подробности —
[H2_3_PACKAGING_2026-11-06.md](./H2_3_PACKAGING_2026-11-06.md).

### Нужен ли Python, если запускать в Docker?

Нет, для Docker-варианта нужен только Docker. Python 3.10–3.12 нужен для
`start.bat`/`start.sh` и ручного запуска. LM Studio в обоих случаях работает
на хосте.

## Режимы и ответы

### Чем отличаются три режима в веб-интерфейсе?

| Режим | Что делает | LLM для поиска |
|---|---|---|
| `5` «Быстрый» (по умолчанию) | BM25 + русский cross-encoder | Нет |
| `2` «Граф» | Entity linking + PPR по графу знаний | Нет |
| `1` «Максимальный охват» | Multi-vector + переформулировка запроса | Да |

Это три измеренных режима. В CLI доступны все 23; остальные — экспертные.

### Нужен ли LM Studio для режима 5?

Для **поиска** — нет. Но веб-интерфейс всегда генерирует текст ответа через
LLM, поэтому для UI LM Studio нужен в любом режиме. Без него поиск может
найти фрагменты, но ответом будет отказ с `llm_unavailable_or_empty`.

### Почему система отказалась отвечать?

Возможные причины:

- в индексе нет подходящих фрагментов (`no_fragments`);
- LM Studio недоступен или вернул пустой ответ (`llm_unavailable_or_empty`);
- модель ответила без валидных ссылок `[n]`, и строгий режим заменил ответ
  отказом;
- вопрос действительно выходит за пределы корпуса.

Отказ — штатное поведение, а не сбой.

### Что означает `confidence`?

Это грубая оценка **заземления**, а не вероятность правильности ответа:

- `0.0` — отказ или нет цитат;
- `0.5` — есть замечания (`grounding_errors`);
- `1.0` — чистое заземление.

### Почему в ответе нет цитат на все найденные фрагменты?

`citations` содержит только использованные источники. Полный retrieval — в
`fragments` и `retrieved_docs`; это диагностика поиска, а не доказательство.

### Что такое page-level режим?

H1-6 добавил поиск, где единица выдачи — страница, а не чанк. Полный путь
прошёл приёмку в M7: **page recall@5 87,0 %** при цели 80 %; на 40 вопросах
H1-1 — 80,0 %. С 2026-11-06 это путь по умолчанию для режима 5 в UI и CLI.
Чанковый baseline доступен через `ASTRO_RETRIEVER_PAGE_LEVEL=0`.

## Данные и приватность

### Где хранится история запросов?

Только в браузере, в `localStorage` (до 50 записей). Сервер историю не
получает. В другом браузере или после очистки данных сайта история пуста.

### Куда попадает обратная связь?

В append-only JSONL `outputs/feedback/feedback.jsonl` (путь можно изменить
через `FEEDBACK_PATH`). Сохраняются вопрос, ответ, режим, оценка, комментарий
и цитаты. IP, user-agent и ID пользователя не сохраняются.

### Мои PDF или вопросы уходят в облако?

Нет, если `LLM_BASE_URL` указывает на локальный LM Studio. Система не
отправляет корпус никуда, кроме настроенного OpenAI-совместимого API.

### Можно ли добавить или удалить PDF через веб-интерфейс?

Пока нет — это задача H2-2. Используйте `python index_pdfs.py` и
`scripts/show_index_stats.py`. Маршруты `/ingest` и `/upload-and-ingest` есть
в API, но в UI не выведены.

### Можно ли пользоваться несколькими пользователями одновременно?

Технически да, но это один общий `API_KEY` без ролей, пользователей и rate
limiting. Для разграничения доступа нужен отдельный слой аутентификации.

## Эксплуатация

### Как выставить систему наружу?

По умолчанию сервер слушает `127.0.0.1`. Для внешнего доступа задайте
`API_KEY`, оставьте `API_KEY_REQUIRED=1` и публикуйте порт через
reverse-proxy с TLS. Не используйте `API_KEY_REQUIRED=0` на публичном
интерфейсе.

### Как обновить индекс?

Остановите сервер, сохраните бэкап, запустите `index_pdfs.py` с тем же
`--output_dir`, проверьте `show_index_stats.py`, запустите сервер. Подробности —
в [ADMIN_GUIDE.md](./ADMIN_GUIDE.md).

### Как сделать бэкап?

Скопируйте каталог индекса `SAVE_DIR`, `.env` и, при необходимости,
`outputs/feedback/feedback.jsonl` и `outputs/qa_cache/qa_cache.json`.
Индекс — обычные файлы, его можно копировать при остановленном сервере.

### Где смотреть логи?

В stdout процесса `uvicorn` или `python main.py`. `/health` показывает
`auth_required` и `auth_failures`; `/search` логирует latency, число цитат и
ошибки заземления. Дашборда пока нет — это H2-4.

## Метрики

### Почему page recall@5 бывает 56,5 %, 73,9 % и 87,0 %?

Это три разных среза, их нельзя сравнивать напрямую:

- **56,5 %** — baseline H2-6 для чанкового режима 5;
- **73,9 %** — лучший из 7 упрощённых page-ретриверов в M8 (ablation);
- **87,0 %** — полный page-level путь H1-6 в M7 (query expansion +
  keyword-boost + CE), он проходит цель 80 %.

M8 показывает, что просто «взять страницу вместо чанка» недостаточно;
полный путь с boost и реранком даёт 87,0 %.

### Как воспроизвести замеры?

Смотрите [HOW_TO_RUN.md](./HOW_TO_RUN.md) §7.2,
[MEASUREMENT_REPORT_2026-11-05.md](./MEASUREMENT_REPORT_2026-11-05.md) и
[H1_6_PAGE_RETRIEVAL_2026-11-05.md](./H1_6_PAGE_RETRIEVAL_2026-11-05.md).
Без индекса и LM Studio доступны только unit-тесты и проверка контрактов.

### Почему answer rate и accuracy были ниже порогов?

В baseline H2-6 они были 73,9 % и 56,5 % у режима 5; у `HippoRAG.rag_qa` —
34,8 % и 8,7 %. Причина — доставка доказательства, а не только промпт.
После H1-6 M7 даёт **answer rate 100 %** и **accuracy 73,9 %** — пороги
пройдены. Остался citation precision **0,621** < 0,80: модель добавляет
лишние цитаты, хотя нужные источники находит (citation recall 0,848).
