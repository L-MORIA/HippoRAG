## 4. Остаток: R-1′ — pre-commit-хук всё ещё валит каждый коммит

Правка R-1 выполнена **как заявлено** (флаг `--select` удалён, добавлен поясняющий комментарий), но практический эффект не достигнут: хук падает по другой причине.

```
pre-commit run ruff --all-files   →  exit 1, 59 errors
```

**Причина:** `extend-exclude` в `[tool.ruff]` (`pyproject.toml:99`) покрывает только `tests/standalone`, `archive`, `outputs`, `htmlcov`. Корневые скрипты `main.py` и `main_dpr.py` не исключены, а **pre-commit передаёт файлы в ruff явно** — для явно переданных путей `extend-exclude` не действует (нужен `force-exclude = true`). CI не затронут: его шаг — `ruff check src/ tests/`, он зелёный.

**Разбор 59 замечаний:**

| Код | Кол-во | Природа |
|-----|--------|---------|
| B023 | 23 | **ложные**: лямбды в `main.py:2774-2797` вызываются сразу в той же итерации (`mode_name, search_fn, has_extra = mode_map[mode]` → `search_fn()`), поэтому late-binding не проявляется. Но паттерн хрупкий |
| F401 | 15 | неиспользуемые импорты в корневых скриптах |
| F541 | 15 | f-string без плейсхолдеров |
| F841 | 5 | неиспользуемые локальные переменные |
| B033 | 1 | дубликаты в set-литерале |

**Рекомендуемое решение (5 минут), любое из трёх:**
1. **Рекомендую:** `force-exclude = true` в `[tool.ruff]` + добавить корневые утилиты в исключения (или `exclude:` в хуке) — корневые скрипты одноразовые, не библиотечный код;
2. `files: ^(src|tests)/` в хуке ruff — сузить хук до библиотеки;
3. Починить скрипты: `ruff check --fix` закроет F401/F541/F841, для B023 — добавить `default=` в лямбды или `functools.partial`.

## 5. Обязательный операционный шаг — переиндексация

**Индекс не переиндексирован.** Файлы на диске датированы 2026-05-14:

```
chunk:  rows=  1422  (7 900 026 bytes)   mtime 2026-05-14 13:48
entity: rows=  6979  (22 379 346 bytes)  mtime 2026-05-14 13:50
fact:   rows=     1  (7 046 bytes)       mtime 2026-05-14 13:50   ← «placeholder»
graph.pickle: 4 286 205 bytes            mtime 2026-05-14 13:50
```

Перекос **6979 : 1 : 1422** означает, что графовая часть HippoRAG (PPR по фактам) на текущем индексе **вырождена**, и поиск опирается преимущественно на dense-retrieval. Это не «грязные хеши» — индекс функционально неполон. Этап 2 меняет hash-ключи сущностей («ё» + единая нормализация), поэтому старые 6979 entity-узлов с новыми несопоставимы.

**Критерии приёмки после переиндексации (предлагаю зафиксировать):**

1. `facts > 100` в новом `vdb_fact.parquet` — не 1;
2. synonymy-рёбра > 0 в графе;
3. `/health` → `facts` ненулевой **и** в логе lifespan нет предупреждения «Факт-стор почти пуст»;
4. соотношение `entities : facts : chunks` сопоставимо по порядку величины (не перекос 7000×);
5. `/search` на русском вопросе находит фрагмент и в ответе `citations[].sources` — массив имён документов.

Готов проверить переиндексацию по этим пяти пунктам отдельным раундом.
