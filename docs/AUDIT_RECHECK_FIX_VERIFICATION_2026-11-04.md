## 6. Функциональная проба S-4 на реальной модели → новая находка N-1

Документ-исполнитель честно ограничил S-4 проверкой по исходнику (§6: «функциональная проверка потребует `pip install -e ".[offline]"`»). Настоящая верификация провела функциональную пробу дешевле: стаб модуля `outlines` + **реальная** модель `sshleifer/tiny-gpt2`, transformers 4.45.2, CPU.

**Результат:** `infer()` падает на реальной модели:

```
File "src/hipporag/llm/transformers_offline.py", line 65, in infer
    input_ids = self.tokenizer.encode(prompt_text)
TypeError: TextEncodeInput must be Union[TextInputSequence, Tuple[InputSequence, InputSequence]]
```

**Причина:** в `infer()` промпт строится как `convert_text_chat_messages_to_input_string(messages_list, …)`, где `messages_list = [messages]` — двойная обёртка. `apply_chat_template` трактует это как **батч** из одного разговора и возвращает **список** строк; `tokenizer.encode(список)` отклоняет (в отличие от `tokenizer(список)`, который батчи принимает — поэтому vllm-путь с той же обёрткой работает).

**Статус находки N-1:** пре-существующий дефект — код идентичен в upstream, `9e881f8` и пре-фиксе; в объём S-4 (три дефекта, заявленные в `7096208` §3.4) не входит и впервые фиксируется здесь. **На вердикт по `1729af2` не влияет.**

**Рекомендация:** одна строка — передавать `messages` без обёртки (как per-item цикл `batch_infer` уже делает), плюс опционально функциональный тест на мини-модели в CI (`pytest.importorskip("outlines")` + крошечная модель) — до «реанимации» offline-режима бэкенд останется неработоспособным end-to-end даже после корректных исправлений S-4.

Все три находки подтверждены независимо, **на настоящей модели**

`docs/AUDIT_OFFLINE_BACKEND_FIX_2026-11-04.md`.

| Находка | Независимое воспроизведение | Исправление |
|---|---|---|
| **N-1** `infer()` падает на реальной модели | подтверждено: `AttributeError: 'list' object has no attribute 'shape'` (у верификатора на transformers 4.45.2 — `TypeError: TextEncodeInput…`; корень один — промпт приходит списком) | промпт строится из **одного** разговора, вход токенизируется тензором и переносится на устройство модели |
| **N-2** free-form `batch_infer` утекает промпт | подтверждено: ответ содержал `'user: Сколько будет два плюс два?\nassistant: …'`, `completion_tokens=86` при 8 сгенерированных | декодируется только завершение; батчевая генерация переведена на **left-padding** (при right-padding модель идёт с pad-токена) |
| **N-3** `retrieve([QuerySolution])` падает | подтверждено: `TypeError: cannot use 'QuerySolution' as a dict key (unhashable type)` | `retrieve`/`retrieve_dpr` приводят `QuerySolution` к тексту вопроса на входе; `dense_passage_retrieval` и `hybrid_retrieval` переживают `QuerySolution` напрямую (и в `StandardRAG`, и в `HippoRAG`) |
| **N-4** *(найдена дополнительно, в документе верификатора её нет)* контракт `infer` — двойка вместо тройки | `BaseLLM.infer` объявляет `Tuple[str, dict, bool]`, четыре места вызова распаковывают тройку, а оба offline-бэкенда возвращали двойку → `ValueError: not enough values to unpack` | `infer()` обоих offline-бэкендов возвращает `(контент, метаданные, признак кэша)` |

**Почему N-4 важна:** без неё исправления S-4 и N-1 вместе всё равно не дали бы
работоспособного бэкенда — распаковка тройки из двойки падала бы на вызове.
Ровно это и означает «ошибка на границе»: не «дефект X не исправлен», а «дефект X
исправлен, но рядом есть ещё один, из-за которого правка не даёт эффекта».

**Регрессионная сила проверена тем же приёмом, что и в §4 этого документа:** новый
файл `tests/unit/test_offline_backend_fixes_2026_11_04.py` (13 тестов) прогнан на
пре-фикс коде (`ded9ace`) — **11 failed, 2 passed**; проходят на обоих ровно два
контрольных теста (обычные строки в `retrieve` и декларация контракта в `BaseLLM`).

**Признано и исправлено по существу:** замечание «S-4 проверен по исходнику, а не
импортом» в §6 этого документа было зафиксировано верно, но вывод «S-4 закрыто»
оказался сформулирован слишком сильно — он означал «три заявленных дефекта устранены
по форме», а не «бэкенд работает». Проверка «дефект X устранён» не заменяет
проверку «модуль запускается»; для модуля, который не поднимается в CI, нужна
хотя бы одна функциональная проба на настоящем токенизаторе.
