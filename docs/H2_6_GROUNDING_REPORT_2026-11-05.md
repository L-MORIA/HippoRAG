## 1. Короткий итог

Механика заземления работает: модель не выдумывает номера источников
(marker validity 1,000), отказывается на 92,3 % unanswerable-вопросов и почти не
оставляет предложений без ссылок. Узкое место — **доставка доказательства в
контекст**: page recall@5 у графового ретрива HippoRAG 8,7 %, у продуктового
режима 5 — 56,5 %.

Из этого следуют два вывода:

1. Пороги H2-6 по answer rate (≥ 90 %) и accuracy (≥ 70 %) недостижимы
   настройкой промпта: при recall@5 56,5 % максимум answer rate — 56,5 %,
   остальное — работа над ретривом (область H1).
2. `qa_top_k` не лечит. Подъём 5 → 8 не улучшает ни один путь: у HippoRAG
   ложные ответы удваиваются, у режима 5 accuracy падает с 56,5 % до 52,2 %.

`a18-meta-zodiac` — цитата на стр. 160 верная, ответ («прокачать сферы
деятельности с помощью ремонта квартиры, метод мета зодиака») покрывает вопрос
частично: в нём нет Солнца и Асцендента, а они в источнике есть — «Для нас
главное, где стоит Солнце, в каком знаке зодиака… Мы его приравниваем к
Асценденту в Овне» (стр. 160). Морфология при проверке учитывается
(`term_matches` сравнивает по основе, «солн»/«асценден» находит и косвенные
падежи), так что это не артефакт метрики: ответ действительно неполный, и
accuracy 0 здесь честная. Правка `gold_terms` была бы подгонкой под ответ
модели — не делаем.

### 5.1. Проверка разметки по корпусу (2026-11-05)

Проверены два вопроса, которые в первой версии отчёта были помечены как
«дефекты калибровки». Проверка шла по тексту книг, а не по ответам модели.

| Вопрос | Что в источнике | Вердикт |
|---|---|---|
| `a18-meta-zodiac` | стр. 160: «Для нас главное, где стоит Солнце… Мы его приравниваем к Асценденту в Овне» | все три `gold_terms` подтверждены, разметка верна, ответ модели неполный |
| `a07-owen-zones` | стр. 7: «соответствует ему прихожая и плита», «Управитель у Овна — Марс» | gold верен; модель ответила ровно по gold, accuracy 1 |

Про `a07` отдельно: в книге есть и другие привязки Овна к зонам — стр. 109
(«Овен — прихожая, лужайка перед домом, по другой классификации — плита»),
стр. 110 («Овен — кухня… бытовая техника»), стр. 111 («гостиная, зал»),
стр. 112 и 126 («крыльцо, порог»), стр. 125 («мансарда, чердак»). Это не
противоречие разметке: там перечислены зоны по **домам гороскопа**, а стр. 7 —
описание знака как такового. Вопрос спрашивает про знак, ответ совпал, поэтому
ни `gold_sources`, ни `gold_terms` менять не нужно — расширение списка
приемлемых страниц подняло бы recall@5 без изменения системы, то есть было бы
подгонкой метрики.

Проверка по номеру страницы безопасна: страницы нумеруются внутри книги, и
метрика сравнивает пару «документ + страница» (`source_key`,
`normalize_doc_title` убирает регистр и `.pdf`). Совпадение номеров у разных
книг (стр. 160 есть и в «Астрофэншуй квартиры», и в «Психологический фэншуй»)
на результат не влияет.

## 6. Решение по `qa_top_k`

Оставляем **5**:

* HippoRAG: 5 → 8 не меняет answer rate (34,8 %), удваивает ложные ответы
  (7,7 % → 15,4 %) и снимает нулевую долю предложений без ссылок (0 % → 20,0 %);
* режим 5: 5 → 8 добавляет один ответ (73,9 % → 78,3 %), но снижает accuracy
  (56,5 % → 52,2 %), citation precision (0,667 → 0,602) и даёт 10,5 %
  предложений без ссылок.

Правило плана «если page recall@5 < 80 %, поднять `qa_top_k` до 8–10» по факту
не сработало: рост контекста добавляет шум быстрее, чем доказательства.
Дальнейший рост качества — только через ретрив.

## 7. Что не достигнуто и почему

| DoD | Факт | Причина |
|---|---|---|
| Answer rate ≥ 90 % | 73,9 % | recall@5 = 56,5 %: 6 отказов из 10 потерь — gold-страницы не было в контексте |
| Accuracy ≥ 70 % | 56,5 % | те же 6 отказов + 3 ответа по чужой странице |
| Citation precision ≥ 0,80 | 0,667 | модель цитирует все использованные фрагменты, часть из них не gold |
| Citation recall ≥ 0,80 | 0,765 | то же |
| Abstention ≥ 90 % | 92,3 % | выполнено |
| False answer ≤ 10 % | 7,7 % | выполнено |
| Marker validity ≥ 1,0 | 1,000 | выполнено |
| Uncited ≤ 10 % | 0 % | выполнено |
