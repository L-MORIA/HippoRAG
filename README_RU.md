# HippoRAG — Поиск по астрологическим PDF

Система поиска по книгам по астрофэншуй с 23 методами поиска, графом знаний, sentence-level индексацией, DAT (динамический альфа) и кэшем ответов.

## Быстрый старт

Полная инструкция — [docs/HOW_TO_RUN.md](docs/HOW_TO_RUN.md), пользовательское
руководство — [docs/USER_GUIDE.md](docs/USER_GUIDE.md), коротко —
[docs/QUICKSTART_RU.md](docs/QUICKSTART_RU.md).
План развития проекта — [docs/ROADMAP_REVISION_DEEPSEEK.md](docs/ROADMAP_REVISION_DEEPSEEK.md) (v1.2, горизонты H0 → H3).

```bash
python -m pip install -e ".[dev]"
python main.py
```

При запуске выберите модель, затем метод поиска и введите запрос.

Веб-интерфейс (H2-1):

```powershell
$env:API_KEY = "your-secret-key"
uvicorn astro_app.web:app --host 127.0.0.1 --port 8000
```

Откройте `http://127.0.0.1:8000/` и введите ключ. Для локального запуска без
ключа: `$env:API_KEY_REQUIRED = "0"`.

## Режим по умолчанию и рекомендация

**По умолчанию — режим 5 «BM25 + RU-CE» (BM25 + русский cross-encoder).** В меню
он помечен «(по умолчанию)», и пустой ввод в строке выбора режима подставляет
именно его. Решение владельца от 04.11.2026 — по замерам H1-3
([docs/H1_3_LATENCY_REPORT_2026-11-04.md](docs/H1_3_LATENCY_REPORT_2026-11-04.md)).
Рекомендованы два режима (⭐ в меню):

| Режим | Когда выбирать | Почему |
|---|---|---|
| **5 «BM25+CE-ru»** ⭐ (по умолчанию) | обычный поиск по корпусу | p95 225 мс (втрое быстрее режима 2), recall@5 97,5 % по документам и **65,0 % по страницам**, LLM не нужен |
| **2 «Граф»** ⭐ | нужен графовый поиск (entity linking + PPR) | recall@5 95,0 % по документам и 60,0 % по страницам, p50 545 мс, LLM не нужен |

Остальные 21 режим — экспертные: у каждого в меню указано, когда он уместен.
Режимы 12 «Self-RAG» и 19 «GraphRAG» помечены ⏱ — по замерам их p95 больше
30 с, поэтому они помечены как экспериментальные и по умолчанию выключены.

> **Первый запуск режима 5 качает cross-encoder `DiTy/cross-encoder-russian-msmarco`**
> (~700 МБ) и грузит его на CUDA. Если модель недоступна, режим не падает: он
> печатает в stderr предупреждение «ПЕРЕРАНК НЕ ВЫПОЛНЕН» — качество выдачи
> в этом случае **ниже измеренного**, и это надо учитывать. Чтобы вместо
> деградации получить ошибку, включите строгий режим:
> `HIPPORAG_REQUIRE_CROSSENCODER=1`.

Бюджеты латентности, методика замера и то, что осталось измерить, —
в [docs/PERFORMANCE.md](docs/PERFORMANCE.md). Основание выбора и его разбор —
в [docs/MAVIS_ROUND3_REMARKS.md](docs/MAVIS_ROUND3_REMARKS.md) §7.3.

## Возможности

- **23 метода поиска** — от BM25 до DAT Sentence-level + LLM
- **Рекомендация режимов** — два рекомендованных и режим по умолчанию, выбранные по замерам
- **Заземлённые ответы** — inline-ссылки `[n]`, проверка диапазона и явный отказ, если ответа нет в найденных фрагментах
- **Веб-интерфейс (H2-1)** — три измеренных режима, цитаты, обратная связь, история в браузере и экспорт Markdown/JSON
- **4 модели LLM** на выбор при запуске
- **Sentence-level chunking** — поиск по предложениям (число зависит от корпуса)
- **DAT (Dynamic Alpha Tuning)** — LLM оценивает два метода поиска и динамически подбирает вес
- **Pattern Search** — точный поиск конструкций «ЗНАК — ЗОНА» (0.3с, без LLM)
- **QA Cache** — автоматическое кэширование ответов, тестирование методов, экспорт для обучения
- **Полностью на CPU** — ни один метод не требует CUDA
- **Русскоязычная доменная область** — астрология, фэншуй, знаки зодиака, планеты, зоны квартиры

## Методы

⭐ — рекомендованный · ⏱ — экспериментальный (p95 > 30 с, по умолчанию выключен)

| # | Название | Описание | LLM |
|---|---|---|---|
| 1 | Multi-vector + LLM | Переформулировка запроса через LLM, мульти-векторный поиск | Да |
| 2 | Графовый PPR ⭐ | Entity linking + Personalized PageRank на графе знаний | Нет |
| 3-4 | BM25/Small-to-big + CE-en | Английский cross-encoder | CE |
| 5 | BM25 + RU-CE ⭐ (по умолчанию) | Русский cross-encoder DiTy + расширение запроса | CE |
| 6 | Small-to-big + RU-CE | Русский cross-encoder DiTy | CE |
| 7 | HyDE | LLM генерирует гипотетический документ | Да |
| 8 | Фильтр + RU-CE | Поиск только в разделе нужного знака | Нет |
| 9-11 | Весь знак | Полный текст/DOCX + LLM резюме/обработка | Да |
| 12 | Self-RAG ⏱ | BM25 → LLM формулирует ответ | Да |
| 13 | RRF + контекст | Ранжирование через Reciprocal Rank Fusion | Нет |
| 14 | E5 sentence-rerank | Мультиязычный E5 для переранжирования | Нет |
| 15 | RRF + sign | RRF + приоритет знака зодиака | Нет |
| 16 | ColBERT-v2 | Late interaction между токенами | Нет |
| 17 | LLM-фильтр | Фильтрация результатов через LLM | Да |
| 18 | Qwen3 + FRIDA | Qwen3 + FRIDA + BM25 | Да |
| 19 | GraphRAG Agent ⏱ | Маршрутизация + самокоррекция | Да |
| 20 | Sentence-level | BM25 по предложениям, группировка по чанкам | Нет |
| 21 | DAT + LLM | Sentence + Dense → LLM → динамический α | Да/fallback |
| 22 | Pattern Search | Точный поиск «ЗНАК — ЗОНА», приоритет классификаций | **Нет** |
| 23 | QA Cache | Кэш готовых ответов, автосохранение | Нет |

## Заземление ответа

Генеративные режимы 12, 19 и 21 отвечают по контракту
`ОТВЕТ / ИСТОЧНИКИ / ОТКАЗ`. Каждое утверждение должно содержать ссылку
`[n]` на переданный фрагмент. Если валидных ссылок нет, строгий режим
(`qa_strict_grounding=True`, по умолчанию) заменяет ответ на
`В предоставленных фрагментах нет ответа на этот вопрос.`; один
repair-retry допускается, но не отменяет проверку.

`POST /search` возвращает:

| Поле | Что означает |
|---|---|
| `answer` | Текст ответа с inline-ссылками или общий отказ |
| `citations` | **Только использованные** цитаты; полный retrieval — в `retrieved_docs` |
| `retrieved_docs` | Все найденные фрагменты — диагностика поиска, не доказательство |
| `abstained` | `true`, если модель отказалась отвечать |
| `grounding_errors` | `no_inline_citations`, `invalid_citations`, `no_valid_citations`, `source_mismatch`, `uncited_sentences` |
| `confidence` | Грубая оценка заземления: `0.0` — отказ или нет ссылок, `0.5` — есть `grounding_errors`, `1.0` — чистое заземление. **Не вероятность правильности ответа** |

Golden set и методика замера — в [eval/grounding/](eval/grounding/) и
[docs/DEEPSEEK_PLAN_2026-11-04.md](docs/DEEPSEEK_PLAN_2026-11-04.md).

## QA Cache

- Автосохранение: каждый ответ → `outputs/qa_cache/qa_cache.json`
- Метод 23: повторный вопрос → ответ из кэша (0.1с)
- `t` в меню — тестирование всех методов, сравнение с кэшем
- `e` в меню — экспорт в JSONL для fine-tuning
